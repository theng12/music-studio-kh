# TuneHarbor release implementation plan

> **For agentic workers:** Use superpowers:executing-plans to implement each task with tests before implementation and an independent review before release. Track each verification result in release/progress.md.

**Goal:** Implement the entire approved first version, produce development installers for all target platforms, and distinguish verified functionality from release gates requiring real devices or signing credentials.

**Architecture:** Preserve the isolated Go profile servers and rooted library operations. Add persistent yt-dlp jobs and FFmpeg conversion, OS-keychain-backed mobile credentials, and a React interface shared by the web server and a Tauri desktop supervisor. Desktop profile administration uses private stdio RPC, not a LAN administration endpoint.

**Tech stack:** Go 1.27.2, SQLite, yt-dlp, FFmpeg, React/TypeScript/Vite, Tauri 2/Rust, OS credential stores, Playwright, GitHub Actions.

**Spec:** ../specs/2026-10-12-music-app-design.md (approved, including six-character numeric passwords and case-insensitive usernames).

## Global constraints

- Windows 11 x64, macOS Intel and Apple Silicon, Ubuntu 24.04 x64.
- No Docker, Python, or terminal setup for the packaged desktop app.
- Shared libraries preserve originals and never overwrite collisions.
- Independent credentials, data, ports, queues, and artwork per profile.
- Local network access is opt-in HTTP for trusted networks; internet hosting is excluded.
- Password minimum six characters; digits alone allowed; usernames case-insensitive.
- Never embed credentials in public URLs or log URLs with secret query parameters.
- No stable-release claim before functional, packaging, and real-client release gates pass.

## Review focus

1. Interrupted processes must not finalize partial audio or leave running child processes.
2. Concurrent profile downloads must not overwrite shared-library files.
3. Missing/changed library folders and OS-keychain failures must pause operations and preserve user data.
4. URLs, filenames, process output and artwork must not become commands, paths outside containment, or executable UI content.
5. Native quit, port conflicts, and profile deletion must preserve music and stop owned processes.

## Task 1 — persistent download jobs

Files: internal/downloads/{queue,runner,url,process_unix,process_windows}.go, matching tests, internal/server/downloads.go, cmd/tuneharbor/main.go.
Interfaces: `Open(dataDir string, importer Importer, runner Runner) (*Queue,error)`; `Submit(rawURL string)(Job,error)`; `Jobs()([]Job,error)`; `Cancel(id string)error`; `Retry(id string)error`; `Close()error`. Importer exposes `Import(string,io.Reader)(library.Track,error)`. Runner exposes `Run(context.Context,string,string,func(float64))(Result,error)` with Result audio paths in private staging.

- [ ] Write real SQLite queue tests: persistence, invalid schemes/hosts/userinfo, failure cleanup, interrupted restart state, queued retry/cancellation, safe finalization, and two queues sharing a library.
- [ ] Run failing queue tests; expect missing behavior. Implement one worker per profile and persisted queued/running/completed/failed/canceled/interrupted states.
- [ ] Implement yt-dlp invocation with argument arrays, bounded logs, private job staging, playlist extraction, progress, timeout and process-tree termination on each OS. Validate every final result is a regular file contained in staging before library import.
- [ ] Add authenticated queue API tests and routes for listing/submission/retry/cancel. Run whole Go suite and race tests; commit only on success.

- [ ] Implement bounded temporary-to-final cache conversion and duration probing; integrate stream format selection without exposing paths. Add WebP decoding and image thumbnail cache invalidation.

## Task 3 — mobile authentication and protocol

Files: internal/secrets/{vault,keyring}.go; internal/server/{subsonic,bootstrap}.go; internal/profiles/profiles.go; tests.
Interfaces: `Vault.Save(profileID,password string)error`, `Vault.Load(profileID string)(string,error)`, `Vault.Delete(profileID string)error`; production AES-GCM keys live in OS credential store, ciphertext in profile data. Browser passwords remain bcrypt hashes. Desktop bootstrap token is one-use, expires in 30 seconds, accepted only from loopback and same-origin POST.

- [ ] Test vault encryption with an injected test credential store, tampering, wrong-profile access and unavailable stores. Test Subsonic MD5 token/salt interoperability, encoded-password mode, XML/JSON error envelopes, pagination, search, duration and artwork identifiers.
- [ ] Implement OS keyring adapter; fail explicitly when secure storage is unavailable rather than storing recoverable plaintext. Upgrade existing profiles only when an owner supplies their password.
- [ ] Test private desktop bootstrap replay/expiry/non-loopback rejection. Implement core protocol compatibility and advertise only implemented extensions. Run all suites; commit.

## Task 4 — desktop supervisor and profile lifecycle

Files: internal/desktop/{manager,rpc}.go, internal/profiles/lifecycle.go, cmd/tuneharbor/desktop.go, tests.
Interfaces: private newline-delimited JSON requests `{id,method,params}` → `{id,result,error}`. Methods list/create/rename/remove/start/stop/settings. Started profiles return local URL and one-use bootstrap credential through private RPC only. Deletion requires explicit confirmed flag and excludes music folders.

- [ ] Test profile create/rename/start/stop, simultaneous instances, port conflicts, data isolation, safe deletion, shutdown and restarted library access. Exercise RPC as an actual subprocess.
- [ ] Implement manager with owned HTTP servers, download queues, conversion workers, periodic scans, per-profile start-at-login preference, and deterministic Close that waits for owned workers.
- [ ] Configure production bundled-tool paths, keyring, and port allocation. Run whole Go suites, real CLI/RPC integration and cross-builds; commit.

Interfaces: Rust owns one manager sidecar; bridges request/response IDs, native folder picker, profile windows, single-instance focus, tray hide/show/quit and optional autostart. Secrets remain private IPC; profile windows consume bootstrap via same-origin POST, never URL parameters.

- [ ] Test RPC bridge framing and shutdown; build native shell and launch under a Linux desktop/Xvfb session. Verify setup without a preinstalled server or tools, tray close, explicit quit and child-process cleanup.
- [ ] Bundle pinned yt-dlp and FFmpeg tools with verified SHA-256, source/license information and reproducible provenance. No unauthenticated tool self-updates. Generate Go sidecars for each Rust target.

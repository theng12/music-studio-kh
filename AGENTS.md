## What this is

A desktop music library and server for Windows, macOS and Linux. The user picks a music folder, imports files or YouTube links (bundled yt-dlp/FFmpeg), and listens in the built-in player or from Subsonic/OpenSubsonic phone apps on the same Wi-Fi. Several independent server profiles can run at once. No Docker, no terminal for end users.

## Verify before claiming done

```sh
go vet ./... && go test -race ./...
npm ci && npm run build:web && git diff --exit-code -- internal/server/web   # embedded assets match ui/
go build -o bin/tuneharbor ./cmd/tuneharbor && go build -o bin/fixture-server ./tests/fixtures/server
npm run test:browser && node scripts/downloads-smoke.mjs
cd src-tauri && cargo test
```

`cargo` needs `src-tauri/binaries/tuneharbor-server-<target-triple>` (build it with `go build -o …`). Routine tests use the fixture yt-dlp. Never make live YouTube or paid calls part of a routine test.

A tracked `.githooks/pre-push` hook enforces `git fsck --full`, `go vet`, `go test -race`, `npm run build:web` + `internal/server/web` asset sync, and `cargo test` before any push (`git config core.hooksPath .githooks`). Never bypass it with `--no-verify`.

GitHub Actions can be blocked by the account's billing. A job that "fails" in 2 seconds with no steps did not run. Never report CI as green without checking that the jobs actually ran.

## Protecting work

- `main` is the integration branch. Work on a branch, open a PR, and merge without rewriting published history. No force-pushes to `main`.
- Never use `rm` for cleanup: move files to `~/Developer/_trash/tuneharbor/`, keeping their structure, and say where they went. `_trash` gets emptied fast, so it's not a backup. Before deleting a branch, record its name and SHA.
- Never `pkill` by pattern. Stop only processes you started, by PID, and check they actually exited.
- Removing a profile must never touch the music folder or audio files. Shared-folder writes never overwrite.
- Never print or commit credentials, tokens, keychain secrets or signing material.
- Ask the owner first before: purchases, signing/notarization credentials, repo visibility or settings changes, deleting anything, releases or publishing, contacting outside people.
